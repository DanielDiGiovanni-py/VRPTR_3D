# Preprocessing and feature construction

These scripts are a public-facing cleanup of the two supplied historical study
scripts. Their scientific operations and output names are retained. They are
not a newly validated preprocessing pipeline, and this release has not been
rerun on the study data. The FSL/Nipype workflow is **not fMRIPrep**.

## Requirements

- Python with NumPy, pandas, NiBabel, Nilearn, Matplotlib, and Nipype.
- A working FSL installation on `PATH`, with `FSLDIR` configured or an explicit
  `--template` path. FSL provides BET, FLIRT, MCFLIRT, SliceTimer, and ConvertXFM.
- Access to the relevant HCP data under its own access conditions. No participant
  data or subject lists are included.
- Nilearn's Schaefer atlas and plotting resources, either cached or available for
  download. `--atlas-cache` selects the atlas cache; `--skip-qc` disables figures.

Original package versions were not recorded in the supplied scripts. No invented
version pins or claims of compatibility with a particular environment are made.
Record your installed versions before use and validate against a small known case.

## Usage

Run these commands from the release root. Paths below are placeholders.

```bash
# Inspect matched runs and existing outputs without writing or running FSL.
python vrptr/preprocessing/preprocess.py \
  --data-dir /path/to/hcp --output-dir /path/to/processed --dry-run

# Preprocess all matching numeric subject directories.
python vrptr/preprocessing/preprocess.py \
  --data-dir /path/to/hcp --output-dir /path/to/processed \
  --n-procs 8

# Build the resting features (the historical script's active stage).
python vrptr/preprocessing/build_input_output.py \
  --data-dir /path/to/processed --steps rest

# Explicitly enable the historical task-GLM helper as well.
python vrptr/preprocessing/build_input_output.py \
  --data-dir /path/to/processed --events-root /path/to/hcp \
  --steps rest task
```

Each script supports `--help` and `--subjects` for an explicit numeric folder
selection. Numeric subject folders are discovered at any length; use
`--subject-id-length 3` in the feature builder to reproduce the historical
three-digit folder filter. The scripts do not select the publication cohort,
assign training/test splits, or implement participant exclusion criteria.

The preprocessing input layout is
`DATA_DIR/<subject>/unprocessed/3T/<run>/<subject>_3T_<run>.nii.gz`, with a T1w
image in the corresponding `T1w_MPR1` directory. Supported run names are shown
by `--help`. Cleaned files are saved in `OUTPUT_DIR/<subject>/`. When the raw and
processed roots differ, provide the raw root via `--events-root` for the task
stage; event files are read from each language run's `LINKED_DATA/EPRIME/EVs`
directory. `story.txt` and `math.txt` must contain onset, duration, and weight
columns, although only onset and duration enter the original design.

## Recorded processing settings

| Stage | Settings present in the source |
|---|---|
| Anatomical extraction and registration | BET fractional threshold 0.3; FLIRT to the FSL 2-mm MNI152 brain template; normalized mutual information, 12 degrees of freedom, trilinear interpolation |
| Functional correction | SliceTimer, TR 0.72 s, slice direction 3; MCFLIRT with motion-parameter output; temporal mean EPI registered to extracted T1 with normalized mutual information, 6 degrees of freedom, 640 histogram bins, trilinear interpolation |
| Spatial transform and cleaning | Concatenated affine transforms; original FLIRT application call; 6-mm FWHM Gaussian smoothing; detrending, standardization, 0.01-Hz high-pass filtering, no low-pass filter at this stage |
| Resting features | Schaefer 100-parcel, 17-network, 2-mm atlas; 0.01–0.1-Hz filtering per run; masker detrending and standardization disabled because images have already been cleaned |
| Parcel connectivity | `ConnectivityMeasure(kind="correlation")` with its library defaults; arithmetic mean of run matrices |
| Voxel-to-parcel fingerprints | Nilearn MNI152 gray-matter mask; independently filtered runs concatenated; columns standardized using NumPy's default population SD; cross-product divided by `T - 1`; one volume per parcel |
| Language target helper | Story/math blocks; SPM HRF; cosine drift, 0.01-Hz cutoff; frame times `arange(T) * TR`; AR(1) noise; explicit design matrices; no added smoothing; story-minus-math and reverse contrasts saved as effect-size maps |

The task helper passes `slice_time_ref=0.5` to `FirstLevelModel`, but the design
matrices are constructed explicitly at the frame times shown above. No claim is
made that this parameter shifts those externally supplied designs. Motion
parameters are generated by preprocessing but are not passed as GLM nuisance
regressors. No susceptibility-distortion correction or ICA denoising appears in
the supplied workflow.

## Outputs and execution behavior

For each processed subject, the feature builder writes:

```text
output/rest_connectivity_100/conn_mean.npy
output/rest_connectivity_100/fingerprint_100.nii.gz
output/task_betas/beta_story_vs_math.nii.gz
output/task_betas/beta_math_vs_story.nii.gz
```

Task files are produced only when the task stage is requested and corresponding
images and events exist. Diagnostic PNGs are generated unless `--skip-qc` is used.
The chosen fingerprint parcel is deterministic with `--qc-seed 0` (the default);
this affects only that diagnostic image, not the arrays or contrasts.

The preprocessing script skips subjects with all expected cleaned outputs. As in
the source, a partially completed subject reprocesses all its selected available
runs, which may overwrite prior cleaned outputs. It creates a unique work
directory per invocation and subject. Existing work directories are never
deleted. Work is retained by default; `--cleanup-work` removes only that newly
created directory after success. Failed work is retained in either mode. Nipype
still uses the original `remove_unnecessary_outputs=True` setting within its own
workflow directories.

The feature builder retains the historical QC-image-based completion checks.
`--force` bypasses them and overwrites generated outputs. A QC image is not proof
that every output exists or that scientific QC passed. Conversely, `--skip-qc`
writes no completion marker, so later runs can recompute existing arrays. Review
the outputs yourself before treating any stage as complete.

## Provenance and limitations

- The supplied feature script's main function executed only resting-state
  processing. Its task-stage call was entirely commented out. This cleanup makes
  that existing call available through explicit `--steps task`; it does not
  establish that this call generated the study's archived target maps.
- Fingerprint normalization is preserved, including its population-SD / `T - 1`
  convention. For finite nonconstant time series this is Pearson correlation
  multiplied by `T / (T - 1)`, rather than exactly Pearson correlation. Zero-SD
  columns are not specially handled. Changing this convention would change the
  study features and requires a separately validated analysis decision.
- Parcel connectivity retains Nilearn's covariance-estimator defaults. It should
  not be described as an explicitly configured unregularized Pearson estimator.
  Defaults and standardization behavior may depend on the installed version.
- The original FLIRT functional-transform call is retained. Full 4D handling,
  grid alignment, and installed-tool compatibility require actual-data
  validation; this cleanup does not certify them.
- The helpers do not supply the original software environment, cohort-selection
  record, QC decisions, split manifest, or proof of original execution.

See `CHANGELOG.txt` for operational changes made during cleanup.
